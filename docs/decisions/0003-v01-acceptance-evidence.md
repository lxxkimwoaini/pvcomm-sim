# ADR 0003：V0.1 独立证据核验及只读回放

日期：2026-11-25。范围：首周协议开发验收，不更改正式实验、标签或数据划分。

采用标准库读取真实 classic PCAP、独立按 TCP 序列重组，核对 TShark 完整 APDU 分母。双端以方向和原始字节核对，主站日志以站点、方向、完整 APDU 字节及 FIFO 对应；保留全部未匹配和实际误差，不按最近时间猜测匹配。解析率仍为 ≥99.5%、工具丢包为 0、P99≤100ms。

维护对照首次检查发现关闭阶段有两条 I 帧和两条 S 帧没有 c104 主站 raw 回调。它们发生在明确记录的 master_business_finished 后、master_stopped 前，属于协议线程关闭尾部。应用回调覆盖区间采用业务运行的左闭右开区间，业务结束后至 stopped+100ms（抓包/日志映射上限）的未匹配帧逐条列入 post_business_capture_tail。业务区间内任何缺失仍失败，额外回调仍失败；关闭尾部全部留在完整解析分母、双端 PCAP/RTU 回调对账及原始证据中，不宣称主站回调覆盖这些尾帧。此区分不改变解析和时间阈值，也不将关闭过程当作业务违约。边界具有单元回归。

Arrow 仅作为可选 data 组。六表显式 schema、单位、观测范围、源/产物哈希和原子版本目录；不覆盖已有产物。新增测试发现 Parquet 会把列表子字段规范化为 element，现显式声明相同子字段，读回按含 metadata 的 schema 严格核验。Windows/WSL 清单路径统一为 POSIX 相对路径。QC 独立报告，不更改原始 manifest。

M2 Web 仅读取服务端预定父目录中的主站白名单和 P0 解析，不读取真值/注入/P1。纳秒以 JSON 字符串传递，浏览器使用 BigInt；回放由后端先执行 available_at 截断。在线状态、缺口、未解析、离线错误如实展示；无真实运行时显示空态。只读页面不承担协议调度和实验资源操作。

当前协议联调继续使用已有 80/100/140kW、固定可用功率及 20kW/s 斜率参数；满足第17.1节三站异容量协议用例，但不代表第3.1节拟定的30/100/300kW正式物理参数。R01/R02是静态站点元数据，尚无区域链路模型。V0.2必须采用经确认的物理参数、气象和潮流验证；本次不修改正式配置或以该测试模型生成论文数据。

维护与中断只做第17.1节规定的开发对照。保留分层审计字段和恢复证据，不声称实现正式标签管线。冻结快照运行可与活动工作区并存；原 code_dirty 标记不改写，另外核对快照全部文件与运行 SHA 的 Git blob、运行配置与快照一致性。该旁证只能证明保留快照内容一致，不能把 dirty 原记录改称 clean。
