# ADR 0028：A01目标链路TCP控制缺口与采集失败分开核验

日期：2026-11-26。状态：实际十站失败定位后实现，冻结复核/重跑待执行。原正常门禁、解析率、抓包工具丢失、时钟对齐及标签定义不变。

真实失败`run_73648bef334d4d7a924199278ae5a191`来自冻结87f50ed十站矩阵。实际R1目标为PV01～PV04；阻断区间[1795702564375788300,1795702569431118549)ns。PV03下行在P0帧1529有TCP seq3944919679、S帧680401003200，所有该段重传都在阻断期，P1未收到。P0帧1767的下一S帧680401004000（seq3944919685）在P1帧80真实捕获，但前6字节永久缺失，因此它保留为TCP待交付残片。原v4以所有P1 incomplete_bytes必须0作数据质量要求，混淆了已证实的故障传输缺口与采集损坏。

新A01 QC v5仅核验：目标站下行、同四元组/连接代次/精确TCP序列、一个6字节完整S帧在已核验阻断区间由P0发出，以及其后一个完整S帧的原始字节和P0/P1帧证据。P1 pending片段必须正好6字节、连续、前一缺口正好6字节；所有条件都成立才把它分类为observed_transport_gap_not_complete_APDU。没有补字节、没有将其加入完整APDU分母、没有声称终端读到它。

应用I帧、U帧、其他长度/缺口、非目标站、阻断区间外、缺来源或歧义证据、回调对账失败仍拒绝。原严格正常QC原样保留；A01报告保留strict_normal_comparison与6字节残片，数值门槛不变。其他检查（包含工具drop0和P99≤100ms）任何一项失败仍导致无效。之前配对中应用回调无P1证据的问题不由本规则解决。

独立PCAP读取器增加TCP起始序列和残片定位元数据，不改变其完整APDU重组/计数。A01另写v5报告，旧v4及原失败/标签不覆盖；标签读取旧冻结v4原件保留回退。新运行使用v5，既有已失败覆盖不静默改成通过，使用新冻结源及原配置复验。
