# ADR 0002：V0.1 使用 c104 实时回环运行器与双路抓包

日期：2026-11-25

## 决策

V0.1 在授权 WSL2 实验环境中使用 `c104==2.2.1` 建立一个主站客户端和三个独立 RTU 服务端。每个 RTU 使用独立回环 TCP 端口和公共地址，主站通过 `Init.ALL` 建立会话并执行总召唤和 `C_SE_NC_1` 有功设定值命令。RTU 仅在 c104 命令回调返回 `ResponseState.SUCCESS` 后更新接受设定值，实际有功由独立的斜率状态模型更新。

运行同时启动 primary 和 diagnostic 两个独立 `tcpdump` 进程，均绑定授权实验回环接口并使用固定端口过滤器；两路 PCAP 的路径、大小、SHA256 和退出码写入 manifest。c104 双端 raw 回调另保存 APDU 级 JSONL，用于端点事件和 PCAP 的交叉核对。TShark 通过显式端口解码覆盖将非 2404 原型端口识别为 `iec60870_104`，生成 packet、APDU、object 三层临时 JSONL。

## 原因与边界

本地端口不能全部使用 2404，因此解析时必须显式 `-d tcp.port==PORT,iec60870_104`；这不改变协议栈产生的 IEC 104 APDU，但必须记录端口覆盖。回环环境只证明协议和采集链路，不代表专网时延或现场设备行为。双路抓包是 V0.1 证据要求的本机实现，后续隔离网络和 P0/P1 物理位置仍需单独验证。

## 验证

V0.1 冒烟测试实际通过，3 个站点各完成总召唤、限发和解除限发；两路 tcpdump 返回码均为 0，TShark 解析可识别 IEC 104/ASDU。30 分钟双路捕获门禁需使用冻结代码和 30 分钟配置单独运行。

## 审查修正

上述双回环捕获仅作为开发稳定性证据，不能证明 P0/P1 独立位置。修正版 `run --isolated` 在主站和每个 RTU 的独立 namespace 中运行独立进程，所有 veth 均在实验命名空间内部创建，不配置宿主接口、路由或 NAT。P0 抓主站接口，P1 抓各终端接口。此前两个 30 分钟回环运行保留，但不作为正式阶段验收。

原平铺字段解析存在包/APDU 一对一、浮点时间精度及对象信息不足问题，已由保留层级的 TShark PDML 解析取代；旧版结果不纳入研究数据。RTU 接受决策发生在命令回调内，随后更新目标并返回 SUCCESS；功率积分只使用命令实际到达后的时间。观测/真值存储由同步记录器隔离。这些修正不更改异常、标签或实验划分规则。

实际回归曾在 P0 报告 7 个内核丢包，原零丢包断言正确失败。保留该失败记录；为减轻突发报文及文件写入调度造成的缓冲压力，显式设置每路抓包缓冲区为 16384 KiB 并记录实际参数。后续仍按真实统计验收，不将增大缓冲视作无丢包保证。
