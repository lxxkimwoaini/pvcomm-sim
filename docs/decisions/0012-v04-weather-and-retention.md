# ADR0012：可扩展历史输入与保留原件的存储策略

2026-11-26。旧`WeatherConfig`及NASA原始/月度哈希、小时零阶保持完全保留。新`0.4-weather-source.1`描述历史输入的适配器/产品版本、来源类别、许可依据及政策/产品地址、访问时间、覆盖区间、经纬度/海拔、原件与规范化哈希。当前只实现`nasa_power_hourly_v1`，没有凭空声称已支持ERA5或许可未明确的高频数据；新API不固定月份或地区，旧版API仍校验原始冻结来源。协议`WeatherProvider.sample`允许后续增加经过验证的适配器。新描述符需要离线原件、政策快照及规范化一致性；不因填了URL就认为获得使用授权。新接口暂不替换旧0.2/0.3物理运行配置；0.4b接入新来源时另验兼容。

存储等级`full_evidence/verified_archive/derived_rebuildable`用于预算及后续归档决策，均不能授权自动删除。默认完整证据。新增gzip归档写新目录、零mtime、逐字节解压哈希/原件再哈希、独立归档manifest，原件始终保留；退出失败只清理本次派生临时目录。原始PCAP、来源、原始事件及既有输出均不删除、不覆盖。

六表和物理Arrow契约不变：增加写出逐值读回及独立QC对源投影逐值校验，避免只检查schema/行数/重写后的产物哈希漏掉值损坏。物理Parquet新写使用zstd，旧文件仍可读，压缩变化不改变表schema。规范化载荷字符串逐值一致。

720h按V0.3实测1,383,250,188B/h和1.5余量保留1,493,910,203,040B，完整备份另计。PDML单文件11,275,084,964B只是临时空间下界，不声称测过总峰值；多个实例的磁盘/内存/吞吐仍未验证。当前只提供只读inventory与预算，不生成正式批量、不删除旧JSONL/PCAP。解析TemporaryDirectory原有生命周期保留，后续管线优化须单列实际临时峰值与失败生命周期证据。
