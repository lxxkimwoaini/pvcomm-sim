# ADR 0029：场景等待期保持真实遥测

2026-11-26。状态：a32bfa4冻结的四次真实正常复验已通过，独立标签无新鲜度违约；2026-11-27按用户要求暂停新增30站实验，详见progress及ADR0030。

有限并发首轮串行N01/N03原件均出现PV01/PV04/PV07/PV10/PV16启动新鲜度违约。以run_2981cc21389a4ea89d1120d2949d2f85为例：PV01初始GI功率在场景-6.635秒到达，顺序完成30站GI/clock后场景开始，首个周期功率在+0.798秒到达。2秒站点既定新鲜度期限5秒在零点前已过，原标签如实记录违约。不能延长期限或在标签中增加启动豁免。

原因是原终端将显式周期上送全部绑定到场景elapsed>0，启动等待的真实协议时间被停报。只为该等待期增加实际单调时钟周期调度，复用同一c104 point.transmit与故障掩码；物理模型和历史气象仍保持场景t=0。开始后仍沿原场景相位及周期，启动报告不消耗场景相位、不补发错过周期。记录reason=startup_periodic、scene_elapsed_s=0，保留实际UTC/单调时间及P0/P1。

不更改标签、新鲜度、通信网络参数、正式业务计划或正常门禁，不修改原运行和失败标签；旧V0.1自动上送路径不受影响。启动流量会变化，是修正实现后的新版本，旧PCAP不承诺逐字节复现。测试需覆盖启动多周期、场景相位、未激活、报告掩码及旧自动路径；随后冻结源码，以原N01/N03配置重新实跑，在两个正常基线通过后才继续有限双实例测量。
