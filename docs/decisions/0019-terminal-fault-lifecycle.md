# ADR0019：复用运行器的终端故障状态与独立证据

按既有单故障计划实施 A04/A05/A06/A08，复用 run_isolated、LinkFaultController 日志和 finally 恢复。RTU 单独加载 Oracle 故障外层，主站保持仅接收正常背景及因果业务数据。新增 0.4-fault.3；旧版本有效。

有界原子状态文件保存实际 RTU 注册点和撤销读回，controller 汇入既有 journal；不反复扫描增长日志。固定 restore 控制只允许本次 event_id，不提供任意命令。上送故障使用 c104 Station.remove_point/add_point 暂停与恢复注册，同时门控显式报告，因此总召唤不能绕过；保留配置点表及物理模型，不修改已生成报文。A04 保留命令确认和显式接受设定值；A06 仅在接受后抑制 1001/1006，保留其他正常遥测。A05 真实协议命令回调等待期间不持有物理锁，返回由协议栈产生确认，不能手工构造响应。A08 首片使用已有单站维护，连接恢复后测量仍不恢复，与一直断联区分。

独立 QC 从冻结配置、实际终端事件、P0/P1 和逐事务证据核验。500ms 作用区间内边缘排除只防止既有基线在途帧被当成抑制泄漏，边缘证据保留；不是修改日志 P99≤100ms 或业务期限。A06 的抑制时长从实际接受开始；A04 各站按自己的周期计数。原始正常门禁不变；开发通过不等于正式标签或覆盖验收。


2026-11-26 S2实际失败后的修正：A05高档15秒全局运行在T1边界发生重连，P0/P1字节完整但12条主站回调未匹配，原实验质量失败，不计验收。改用c104 2.2.1真实支持的ResponseState.NONE及服务器Point.transmit(ACTIVATION_CON)延后正确认；上游Server.cpp的lazy confirm previous control command分支由协议栈构造ASDU，不手工拼报文。待处理槽有界、同站串行，主循环只在到期执行，不阻塞协议读线程或物理模型。取消清空待处理命令，不接受已取消操作；正常撤销不丢弃已经排队的处理。

固定依赖的公共API没有延后否定确认的负标志设置。若延后处理时设备实际拒绝，实验明确失败并保留证据，不能伪造正确认、假称收到否定确认或将该不支持组合标为验收通过。正常N09/P06正常成员的即时真实否定确认不受影响。此限制不更改A05期限/强度或标签；首片已授权A05用例及P06改变成员在处理时均具备接受条件。后续扩展该组合需单独验证协议栈支持。
