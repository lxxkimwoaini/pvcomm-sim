# ADR0016：独立故障外层与自有桥端口中断

2026-11-26，V0.4c首个切片。仅实现A01；A02/A04/A05/A06/A08仍按原计划后续推进。候选持续时间保持5/20/60s，既有正常配置、期限和数据质量门槛不变。

新增`0.4-fault.1`组合契约，包含既有正常背景与唯一故障事件。站点集合、区域和全局范围使用互斥结构，实际目标从已验证站点配置展开。故障原始/有效配置和操作证据仅存`truth/fault/`；主站仍只取得原正常业务调度，不取得故障计划。原正常`run-scenario`保持原语义，新增显式`run-fault`及独立诊断QC。

A01通过自有区域桥的接入端口或汇聚端口转发状态从forwarding(3)切换为disabled(0)实现。保留veth管理状态和两端采集，真实阻断桥转发，不发送STOPDT、不停止RTU或电力模型。直接关闭采集所在接口可能同时破坏端点采集边界，因此首片选择桥转发阻断；此机制是隔离实验链路不可用，不宣称现场硬件断线。操作仅允许本次创建的已知桥端口，修改前读回基线、修改后核验、撤销后恢复原值。配置中不接收命令、namespace或接口名。

所有操作记录请求、前后读回、单调/UTC/逻辑时刻及失败；多端口非原子操作逐项留痕，不把计划时刻当实际施加时刻。退出时在进程和抓包停止前撤销已触及端口，失败保留并使实验完整性失败。故障撤销不等于业务恢复；独立QC用真实P0/P1、主站收到的遥测、物理更新和清理证据分别核验作用与恢复。

首片报告只给运行质量、施加事实、通信影响及已有事务结果，不输出正式`service_violation`标签。注入成功但无明确影响须如实保留，不能按配置强制生成异常。原正常门禁继续严格要求P0/P1一致；异常实验仍要求各端采集与各自回调对应、完整解析、时间对齐、物理重算和Arrow。正式分层标签与配对属于V0.4d。
