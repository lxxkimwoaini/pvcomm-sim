# ADR 0023：分组维护与部分业务恢复

日期：2026-11-26。状态：实现已进入回归与真实实验验证；不是阶段验收结论。

复用现有隔离运行器、c104、TerminalFault、物理模型和标签流水线。新增场景契约0.4-scenario.2的maintenance_windows，不改变V0.3电力配置。每个维护计划明确身份、站点清单、站点组或区域范围和起止逻辑时间。区域清单必须与通信区域成员完全一致；当前首版每站只允许一个维护窗口，重复站点在配置阶段拒绝，避免信号和恢复证据交叉。维护期间及原15秒恢复观察期不得安排该站正常调控任务。

旧0.4-scenario.1序列化不增加默认字段，保持源文件及嵌套规范哈希兼容；旧单站interruption通过适配器复用原计划。新旧维护字段不能混用。旧正常和终端QC仍使用v2；只有分组维护使用对应v3目录，不要求重写已经保留的v2证据或标签。

主站只读取合法业务场景，提前发布逐站维护授权，不读取故障目标。每站独立线程完成STOPDT/关闭握手、独立就绪文件、连接恢复及GI；控制器只向该站所属进程发送既有暂停/恢复信号。线程失败终止并保留整次实验，不把握手失败当作业务异常。端点关闭期间物理tick持续。维护时间用统一场景起点的整数纳秒计算，避免浮点转换改变计划边界。

A08目标允许是维护组的子集。全部失败、部分失败及区域故障仍是同一个A08事件，不增加异常类型，也不从维护授权推导标签。原终端抑制/撤销/回读和双端PCAP核验负责实际作用；独立维护核验同时记录连接OPEN、有效GI确认/结束和1001/1006有效业务数据恢复。业务数据恢复不代表功率已经正确执行命令，执行恢复仍按既有事务证据判定。固定恢复期限仍为15秒，不因配置扩大而延长。

真实验证使用三站区域全部失败、同一区域仅一站失败、跨区域部分站点维护三种情况。保留未维护站在维护期间实际命令及响应，核对每站标签、物理连续性、原QC门槛、无丢包及资源清理。真实实验必须在冻结代码下执行并保留持久目录；没有实测结果前不记为通过。

实测补记：7666306的混合用例中PV01在终端恢复监听前发起连接，随后OPEN迟到约66秒，机制QC失败且原件保留。bade029增加与初次rtu.ready同类的维护进程恢复就绪握手，再执行真实连接；等待仍限制在原15秒期限内，不读电气状态或未来业务反馈，不写入M2观测。连接、GI及遥测依然必须由真实协议证明。另修正验收测试：没有故障的站点其顶层故障恢复字段不适用，不能要求其具备不存在的故障恢复事件；受故障影响站点的恢复及截尾要求保持不变。
