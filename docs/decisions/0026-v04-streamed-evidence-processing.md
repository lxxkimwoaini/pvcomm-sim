# ADR 0026：分批Arrow及按站点证据索引

日期：2026-11-26。状态：实现、普通回归及既有混合A08原件等值复核已通过，并已完成单次小运行性能测量（见证据处理报告）；30站处理峰值及吞吐仍待实测。

六表Arrow导出改为4096行分批写入，QC逐批与原JSONL逐行比较，文件SHA256使用有界块读取。保留schema、scope、纳秒整数、zstd、必要字段非空、全部行等值及来源哈希；转换前后再次核对来源未变，临时目录完成核验后原子提交。旧Parquet可继续逐批核验，不要求旧文件字节或行组布局与新输出一致。10,003行负测试覆盖最后一批被篡改且manifest重哈希的情况，禁止整体JSONL/Parquet读取仍可完成往返核验。

标签输入默认采用临时SQLite证据索引，按原始文件顺序逐条校验run_id及唯一记录键，将原JSON payload及路径仅存一份，缓存8MiB、排序落盘。身份映射仍指向原文件哈希和原记录ID，不指向临时数据库。标签生成与独立QC使用按站点视图；保留无站点的全局业务起止/覆盖记录，协议对象按实际CA与端点地址关联站点。独立QC继续独立重算判据，不读取生成器的判断结果。

临时索引仅供Oracle离线处理。CLI和批量运行器不把它提供给M2；无未来信息、真值或标签字段进入在线接口。索引调用使用上下文管理，成功、异常或输入无效时关闭连接并仅清理本次创建的临时目录，不删除任何原始证据。测试fixture可明确选择原可变列表路径；四类业务结果和新鲜度缺口同时验证两条路径生成的完整标签及证据完全相等，不改标签schema或v3判据。

该改动消除六表全量共驻、完整文本副本和跨站无差别扫描；不宣称整个QC全流程已实现常量内存。现有QC报告JSON、单站时间序列及最终站点标签仍会驻留，电力扩展表和其他QC尚有列表消费者。真实30站峰值、临时索引峰值和吞吐必须实测。profile_v04_evidence.py在保留运行上重新计算并与原标签相等核验，写入全新外部报告目录，不改写已有标签或QC。其Python追踪峰值不包含原生库RSS。
