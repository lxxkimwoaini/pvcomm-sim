# 服务器三站正常数据：两路验证与四路生产

本轮仅复用冻结应用5f4cf2d、已有normal_job、BatchConfig和串行run_batch，生成48个1802秒片段（各含2秒预热，累计24小时有效通信）；不是连续24小时。6月27～29日保留独立测试。先核对所有有效、失败及排队来源，选择未占用的6月14日；本地6月12日队列、服务器6月13日一小时任务不改动、不重复。

在应用仓库外部署一个版本化薄脚本，冻结两路各1项和四路12/12/11/11项清单。每Worker独立Python进程，经run_userns_lab.sh创建私有user/mount/network namespace；独立输出、SQLite锁、TMPDIR、日志和资源采样。所有BatchConfig.maximum_concurrency保持1，run_batch源码及串行循环不改。薄driver仅在execute_job调用边界包装资源准入，然后调用原函数；资源不足时等待，不启动仿真、不消耗额外重试。每个任务仍由原run_batch完整采集、解析、导出、QC、标签及清单哈希。

全局准入累计所有未完成任务的剩余尝试最坏留存预算，加并行解析临时下界和至少20GiB余量；同时要求MemAvailable至少16GiB。启动Worker及每次真实尝试前均重新检查，监控记录持续保存。正常活动任务不因资源预警强杀。所有任务最多两次，失败原件不删。协调进程与Worker分别加本地进程锁；续跑核对应用SHA、clean、脚本及全部配置哈希，同一输出调用原resume，不重跑已完成项。

先等待原一小时任务完成且业务/标签QC通过，再运行两个不同时段的半小时真实任务。两路均须完整APDU匹配100%、四路抓包drop=0、正常及标签QC通过、invalid/uncertain/违约站点均0、cleanup_errors=[]；复核原始和派生SHA以及命名空间/输出隔离。只在两路全部通过及四路全局预算通过后启动余46项；资源不足则维持最多两路。

交付parallel-index.json、资源采样、每Worker原manifest/summary/执行锁、独立门禁核验、实际完成数/有效时长/资源/容量和续跑命令。代码、轻量负测试及文档提交推送；数据、私有连接信息及运行证据只留服务器。不训练、不改科研参数、不进行其他规模或异常实验。
