# V0.4 接续执行与阶段门禁

依据用户本轮审查要求及 V1.3，不增加异常类型、不修改既定强度、期限、标签主任务或数据划分规则。基线为 feat/v04-scenarios / 7415d33，原运行、标签和 QC 全部保留。不合并堆叠 PR。

按依赖顺序实施下列可验证切片，每片执行相关回归、冻结代码、真实原件核验或新运行，更新进度并普通推送。

1. **配对及标签缺陷修正**：`qc/pairs.py` 逐目标站核验正常/改变成员及非目标站，区分数据质量和业务对照并同时纳入总门禁；invalid/uncertain/null 不作负例。`pipeline/labels.py`、`qc/labels.py`、`domain/labels.py` 仅修复有证据的事务截止、覆盖、迟到确认和恢复问题，新版本目录保存结果。增加负测试，在原四组配对上重新核验，不重跑原实验。A05 延后否定确认不支持组合提前校验。
2. **统计相似性及重复机制**：冻结可机器读取的特征、窗口、距离、阈值和匹配策略，明确工程阈值依据和开发/评估用途，目标站局部及全局分别统计方向包数/字节、包长和间隔分布、速率、突发、有效持续时间。有界扫描 P0，结果含原件哈希、参数哈希及未匹配原因。新种子、历史日期和业务条件形成预冻结矩阵，不改包、不按检测模型筛选。报告尝试/有效/业务对照/相似四种计数。
3. **A08 多站和区域维护**：扩展配置及原隔离运行器的维护生命周期，提前发布逐站合法计划；支持同一维护中部分成功和部分失败，独立记录连接/协议/业务恢复，物理持续、未选站业务正常。保持旧单站配置复现。单元、负测试后开展真实多站及区域验证。
4. **批量流水线**：复用 run-isolated/run-pair/parse/label/QC，版本化矩阵、唯一身份、队列、状态、有限重试、中断续跑、结果索引、独立运行覆盖计数、容量预算。失败不覆盖、不删除原始证据。验证来源/校验和和幂等拒绝覆盖，先小规模真实执行再扩展。
5. **规模及覆盖**：3→10→30站，按六类既定档位和范围推进每类40次独立有效运行；不得用站点或窗口数代替运行数。保留故障无业务违约的有效样本和相似性未匹配样本。采集、解析、物理、因果、标签、清理门槛保持不变。按实测验证压缩、临时峰值、有限并发吞吐。
6. **科研工作台**：在现有 Vue/FastAPI 上接入受控场景/队列、覆盖、诊断时间轴、配对统计/曲线、证据定位、QC、清单与导出。M2 与 Oracle 后端分离，Web 不接收任意命令，UI 不干扰协议计时。真实 API/浏览器验收。
7. **V0.4 总验收**：逐项汇总 N01–N10、六类机制、多站/区域、配对和统计匹配、标签、重复覆盖、30站、工作台、批量/资源。明确部分完成和阻塞，未达门禁不推进 V0.5。
8. **V0.5（有条件）**：仅在 V0.4 门禁实际通过后，先来源/运行/配对组划分再60秒右对齐因果窗口（步长5秒），实现 M0/M1/M2 白名单和 available_at 截断、窗口标签边界、预发布清单及泄漏审计。保留同等业务信息规则基线，M3待真实独立来源。不启动720小时或创新模型训练。

本文件为执行顺序，不是验收结果。各项实际命令、源码冻结、原件路径和测量写入 progress 与对应报告。
