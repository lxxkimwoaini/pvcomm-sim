# V0.4d 配对与正式标签执行切片

依据 V1.3 第9、10、12节和现有 V0.4 总计划直接实施，不变更异常定义、强度、业务期限或正式划分规则。A04/A05/A06/A08 冻结矩阵运行期间只开发离线处理与配对契约；矩阵结束且资源清理后才运行新配对。

1. `config/pairs.py`：P03（授权维护/未授权中断）、P04（相同资源不足背景/接受后反馈缺失）、P06（相同设备操作/合法拒绝与迟到确认）及维护后 A08。明确允许的成员差异；共享气象、设备、拓扑、网络基线、种子、初态、时钟和业务计划哈希，禁止任意排除字段。
2. `domain/labels.py`、`pipeline/labels.py`：按站点输出故障诊断、命令业务约束与接收新鲜度记录；故障施加不能代替业务判定。明确左闭右开区间、UTC纳秒、在线可判定点、恢复、截尾、证据文件哈希与原始事件引用。仅写 `labels/`，不修改原始证据、observed 或历史 QC。
3. `qc/labels.py`：独立从原始主站事件、协议对象、设备证据及既有机制 QC 核验外键、期限、因果性、覆盖与证据完整性；不以重新调用标签生成器自证。缺证据保留 uncertain，运行质量失败为 invalid。M2 不加载标签、注入配置或 P1。
4. CLI `label --run-dir` 与 `qc --profile labels`，Arrow及JSON schema、字典、负测试同步。`split/features/benchmark` 仍未实现。标签输出为科研开发契约，不声称完成正式数据集。
5. 配对使用原 `run_isolated`，唯一运行号与独立输出；固定比较方向包数、字节数、持续时间和到达间隔均值/P50/P95，保留真实差异及未匹配。正常成员仍经过严格正常场景 QC；异常成员经过机制与质量 QC。

验收：单元负测试覆盖错run/重复证据、期限提前、未来事件、标签伪造、未知确认、资源不足、合法拒绝、维护豁免及恢复失败；三站真实四组配对，每成员独立QC，标签QC与共享条件QC。缺少真实运行、覆盖或证据时明确保留未完成状态。本切片不运行30站正式数据、720小时或模型训练，不自动合并PR。
