# V0.4 有限并发实测切片

沿用 V0.4 接续计划的资源门禁，不改变生产队列 `maximum_concurrency=1`、场景参数、质量门槛或数据保留策略。

代码范围：`scenario/concurrency_profile.py` 和薄入口 `scripts/profile_v04_concurrency.py`。调用同一 `run_v04_batch.py`，每个子队列独立输出、GNU time、进程和存储采样；外层仅协调有限任务并记录同时资源占用，不新建仿真运行器。

在所有规模实验退出并清理后，从新的 clean 冻结源码执行固定 N01（30站、seed920001、variant0）及 N03（30站、seed920002、variant1）两个正常模板，先串行1实例，再并发2实例。共四个不同 run_id；同一模板在两个设置的完整配置相同。运行前保存完整矩阵、源码版本及存储预算。不与其他 PVComm 网络实验重叠，不启动剩余228项或720小时正式生成。

验收：四次真实 c104/物理/双端采集运行分别经过原正常 QC、Arrow和标签独立核验，子队列保留文件大小及 SHA 全部复核；采样无错误、非空、有正耗时、运行身份不重复、网络资源清理。串行设置失败时不执行并发；任一设置失败不计算通过的加速比。失败、日志、PCAP和临时峰值记录保留，不调整期限或抓包/解析/对齐门槛。

1秒采样报告同时RSS、CPU估计及解析/PDML/索引存储峰值下界；不同时间的两个队列峰值不相加冒充同时峰值。RSS含共享页重复，短时进程及峰值可能漏采，CPU增量受进程退出影响。四次短时正常实验不能证明异常持续吞吐或720小时资源安全；测量结果用于后续预算及并发决策。

普通测试只用明确合成的记账夹具，覆盖配置固定、磁盘不足/实验重叠阻断、哈希变更、源版本不符、采样失败、空采样、重复身份、失败停止和原件保留，不能计作吞吐实测。

复现入口（仅授权Linux，输出必须为冻结源码外的新目录）：

```sh
PVCOMM_ALLOW_LAB=1 PYTHONPATH=src /mnt/e/project/pv/.venv-wsl/bin/python \
 scripts/profile_v04_concurrency.py --output /var/lib/pvcomm/runs/v04_concurrency_new
```
