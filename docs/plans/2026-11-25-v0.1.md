# V0.1 最小 IEC 104 协议原型实施计划

日期：2026-11-25。依据：`AGENTS.md`、V1.3 方案第 5、6、11、17、21 节。

## 范围

本切片实现本机 WSL2 隔离回环环境中的 1 个 c104 主站和 3 个独立 c104 RTU 服务端。每个 RTU 使用独立 TCP 端口和公共地址，提供有功遥测、已接受有功设定值、运行状态和有功设定值命令。主站建立真实 TCP/IEC 104 连接，执行启动、总召唤、有功限发和解除限发；RTU 只有在命令回调返回成功后才更新接受设定值，电气状态模型随后按斜率更新实际有功。

同时记录 tcpdump 原始 PCAP、c104 双端原始 APDU 回调、主站业务事件、终端事件和电气状态。输出按 `run_id` 隔离，运行配置和清单写入输出目录。当前切片不连接外部地址、不创建 namespace/veth、不修改宿主网络、不生成正式数据集。

## 文件与职责

- `src/pvcomm/scenario/v01_models.py`：V0.1 严格配置模型及 YAML 加载。
- `src/pvcomm/capture/tcpdump.py`：tcpdump 启停、接口和退出状态记录。
- `src/pvcomm/protocol/c104_runtime.py`：c104 RTU、主站、点表和回调适配。
- `src/pvcomm/scenario/v01_runner.py`：唯一运行编排、时间线、输出和清理。
- `configs/v0.1-lab-smoke.yaml`：短时冒烟配置。
- `configs/v0.1-lab-30m.yaml`：V0.1 正常运行配置，目标 30 分钟。
- `tests/lab/test_v01_runtime.py`：显式标记的真实协议集成测试。

## 测试与验收

1. 普通 Python 检查、schema 和现有 49 项测试继续通过。
2. WSL 中运行短时真实 c104 测试，检查 3 个连接均为 `OPEN`，3 次总召唤、限发和解除限发均有主站事件及 RTU 接受事件。
3. PCAP 能由 tcpdump 生成且包含 2404 业务以外的配置端口流量；TShark 能识别 `iec60870_104`/`iec60870_asdu`。
4. 输出清单记录配置哈希、代码 SHA、工具版本、捕获退出状态和实际运行状态；异常退出也保留目录。
5. 30 分钟正式 V0.1 门禁仍需单独运行并核对包计数、解析率、日志关联 P99 和资源清理，未完成前不标记 V0.1 通过。

## 冒烟实施结果（2026-11-25）

短时真实运行与显式 `pytest -m lab` 已通过。3 个 RTU、总召唤、限发/解除限发、tcpdump 和 TShark 解析均有实际输出；30 分钟门禁仍是下一项任务。

## 风险与边界

- c104 2.2.1 的回调签名由扩展模块严格检查，适配层必须保留实测签名。
- 回环抓包证明协议报文和本机实验链路，不代表物理网络或现场性能。
- 当前设备状态使用明确的容量、可用功率和斜率仿真假设；气象、潮流和异常注入留待 V0.2/V0.4。
- 输出 JSONL 是 V0.1 运行证据的临时交换格式，正式 Parquet 解析和数据集契约仍待后续阶段。
